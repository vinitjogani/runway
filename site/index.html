How it works

A compiler, not an emulator.

Your app compiles to a native binary with the Swift toolchain for Linux and Windows. Runway supplies everything Apple’s SDK would, and rewrites the few things Swift can’t do off the Mac.

  1. 01

    Reads your project

    Xcode projects and workspaces, Swift packages and XcodeGen specs: targets, build settings, xcconfig, Info.plist, asset catalogs, string catalogs, storyboards and XIBs. Dependencies are fetched at their pinned versions.

  2. 02

    Rewrites what Swift can’t do

    There’s no Objective-C runtime off the Mac, so @objc, #selector, target–action, KVO and KVC become plain Swift. Line numbers are kept, so errors and stack traces point at your code.

  3. 03

    Links Apple’s frameworks

    SwiftUI, AppKit, Combine, Core Graphics and dozens more, reimplemented from scratch under their real module names. import AppKit just works, and so does Auto Layout.

  4. 04

    Draws it natively

    GTK 4 on Linux, Win32 on Windows, styled after macOS: traffic lights, pill buttons, switches and SF Symbols names drawn as matching line art. Menus go on the desktop’s global menu bar when it has one.

Zero porting code

Point it at any source.

Runway never contains a line written for one app. If something is missing, it’s added to the frameworks for every app.

Looks like the Mac

Not a lowest common denominator.

SwiftUI keeps its own layout rules and AppKit its own controls, so your app keeps the spacing, type and feel you designed.

Light on memory

No browser in the box.

A native binary on the system toolkit. Flight (notes) runs in about 67 MB of memory on Linux.

Questions

Before you take off.

Do I have to change my app’s code?

No. Runway builds the same source you ship on the Mac, including #if os(macOS) branches. If your app uses something Runway doesn’t have yet, runway check lists it, and the fix goes into Runway, not your app.

Is this an emulator or a web view?

Neither. Your Swift compiles to a native binary for Linux or Windows. Runway reimplements Apple’s frameworks in Swift and draws with the platform’s own toolkit, GTK 4 on Linux and Win32 on Windows.

Does Runway contain Apple’s code?

No. The frameworks are written from scratch against Apple’s public documentation, and SF Symbols names are drawn with Lucide, an open icon set. Your app links Runway’s modules in place of Apple’s.

What about features only Macs have?

They report themselves unavailable, the way they would on a Mac without the hardware or permission: no Apple Intelligence model, no Sparkle updates, no accessibility trust. Apps already handle those cases, so they keep working.

When can I use it?

Now, from source, on Linux. It is an early preview: simple SwiftUI and AppKit apps build today, and the corpus scoreboard tracks how far the larger ones get. A public Swift package and Windows builds come next.
